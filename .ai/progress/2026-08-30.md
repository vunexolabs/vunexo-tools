# Session 2 — PDF generation

Picked up the "Next up" list's item 1. Everything from the earlier sessions was already committed as `6209e06` before this started (`CURRENT.md`'s "uncommitted work-in-progress" warning was stale — corrected there now).

## Library choice: `printpdf` 0.12, `default-features = false` + `text_layout`

Composes the invoice operator by operator (`Op::ShowText`/`DrawRectangle`/`DrawLine`/`UseXobject`), which is what "real layout control, not print the webview" needs. Dropping default features drops the `html` feature and the whole azul-layout/fontconfig HTML-to-PDF stack with it.

`text_layout` had to be added back for one specific reason, found the hard way: **font subsetting only exists on that feature.** `prepare_fonts_for_serialization` has a `#[cfg(not(feature = "text_layout"))]` arm that always embeds the full font. Without it a one-page invoice came out at **743 KB**; with it, **32 KB**. Same document, same code otherwise. Worth the dependency.

Note the API differs between the two configurations — `ParsedFont` is a stub struct without `text_layout` and a newtype over azul's with it (`face.font_metrics.units_per_em`, `get_glyph_width_internal`, not `face.units_per_em`/`get_glyph_width`). `src/infrastructure/pdf/fonts.rs` targets the `text_layout` shape.

Also raised the crate's `rust-version` 1.77 → 1.88 (printpdf 0.12 requires it; local toolchain is 1.98).

## Embedded font: DejaVu Sans 2.37, Regular + Bold

`src-tauri/assets/fonts/` (+ `LICENSE.txt` — Bitstream Vera, permissive). The PDF base-14 fonts carry no `₹`, `₦`, `₫`, `₺`… and the app prints in 55 currencies, so an embedded face was unavoidable. DejaVu covers every symbol in `lib/currency.ts` **except** Bengali `৳` (BDT) and `﷼` (SAR) — verified with fontTools against the actual table, not assumed.

Those two are handled rather than ignored: `Fonts::can_render` checks glyph coverage at render time and the renderer prints `BDT 2,360.00` instead of an amount with a silently-dropped symbol. Same fallback covers a currency code the table doesn't know at all.

Subsetting means the 1.4 MB of source faces cost a few KB per output file.

## Layering

Kept to `architecture.md` rule 3 — `printpdf` never leaves `infrastructure/pdf/`:

- `domain/currency.rs` — Rust mirror of `lib/currency.ts`'s `CURRENCIES` (symbol + ISO 4217 decimals), plus grouped formatting. **Keep the two lists in sync.** Indian lakh/crore grouping for INR/PKR/LKR/NPR/BDT, uniform thousands elsewhere; the frontend's own formatter has no grouping, which is fine on screen but not in print.
- `domain/invoice_pdf.rs` — `InvoicePdfDocument`: every string the PDF shows, already formatted. Snapshot-vs-live resolution, the CGST/SGST/IGST decision, date/quantity/basis-point formatting, the totals rows all live here, testable without producing a byte of PDF. **This is `split_gst`'s first real server-side caller** — it and `GstSplit` are no longer dead code.
- `application/ports/invoice_pdf_renderer.rs` + `application/pdf.rs` — the port and the orchestration (load invoice/settings/business/customer/payments, build the document, call the renderer).
- `infrastructure/pdf/{fonts,canvas,invoice_renderer}.rs` — measurement, placement, pagination. It formats nothing.

One deliberate seam: money amounts cross into the renderer as **numbers only**, no symbol. Whether an amount can print as `₹1,234.00` or has to degrade to `INR 1,234.00` depends on the embedded font's glyphs, which only the renderer knows.

`canvas.rs` works in **millimetres from the top-left**; the flip to PDF's points-from-bottom-left is confined to one function.

## Template

A4, one page per ~14 line items, `#/DESCRIPTION/QTY/RATE/TAX/AMOUNT`. Letterhead (logo box + business identity, title + meta on the right), Bill To, line-item table, right-aligned totals, notes/terms beside payment details, `Page N of M` footer. Descriptions wrap and repeat the column header band across pages; totals never overprint the footer. `DRAFT`/`CANCELLED` render as a diagonal grey stamp on **every** sheet.

Type styles are named constants (`TITLE`, `SECTION_LABEL`, `TOTAL_STRONG`…) rather than loose role/size/colour triples at each call site.

## Behaviour worth knowing

- **Previewing a draft works.** A draft has no snapshot yet (`user-flows.md` §5 — it's taken at Issue), so the use case falls back to the live business/customer records for `DRAFT` only. An issued invoice always prints its own frozen snapshot.
- **Outside India the totals print one neutral `Tax` line**, not CGST/SGST — this app doesn't compute any other country's breakdown, so it must not print one. The Invoice Editor's on-screen totals were changed to match (they previously split unconditionally); screen and PDF now make the same call.
- **Overpayment**: balance clamps at zero and an `Overpaid by …` note prints, per `user-flows.md`'s editing rule — never a negative amount due.
- A missing/moved logo file is not fatal; the invoice renders without it.
- File name: `Invoice-INV-2026-0007.pdf`, or `Invoice-draft-12.pdf` before issue. Sanitized, since `invoice_number_format` is user-configurable and nothing stops a `/` in it.

## Save / print path

`render_invoice_pdf(id)` returns base64 (Tauri would otherwise serialize `Vec<u8>` as a JSON array of numbers) → `invoicePdfObjectUrl` → `<iframe>`. The preview shows the **actual rendered PDF**, not an HTML lookalike — a second template in React would drift, and the webview's PDF viewer already provides scroll/zoom/print.

`save_invoice_pdf(id, path)` **re-renders server-side** rather than accepting bytes from the webview, so the frontend can't write arbitrary content to disk under an invoice's name. The path comes from `@tauri-apps/plugin-dialog`'s `save()`; added `tauri-plugin-dialog` (Rust + JS) and `dialog:allow-save`/`dialog:allow-open` to `capabilities/default.json`.

New `FileWriter` port + `StdFileWriter` — a real seam the `.vbx` backup work will reuse, rather than `std::fs` inside a use case. (`InfrastructureError::Io` is now constructed, so that warning is gone too.)
